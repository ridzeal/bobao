## Root Causes & Fixes

### Bug 1 — `BOB_API_KEY` not reaching the child process (primary bug)
**File:** [`bob-run.js`](bob-run.js)

Next.js automatically loads `.env` into its own process, but **child processes it spawns via `spawn()`/`execFileSync()` do not inherit that**. `bob-run.js` is a plain Node script executed as a subprocess, so it starts with no `BOB_API_KEY` and bob fails with `Error: Bob API key is required`.

**Fix:** Added a manual `.env` loader at the top of `bob-run.js` that reads `__dirname/.env` before calling `execFileSync`. Also replaced the hard-coded `bobPath` with `process.env.BOB_PATH` so the `.env`-defined `BOB_PATH` is honoured too.

---

### Bug 2 — Bob's greeting message falsely flips session to `blocked`
**File:** [`lib/live-bob-provider.ts`](lib/live-bob-provider.ts)

Bob's greeting ends with `"What can I assist you with today?"` — a sentence ending in `?`. The `BLOCKED_PATTERNS` regex `/\?\s*$/` matched it, causing `pushLine` to mark the session as `blocked` even though Bob had already exited with code 0.

**Fix:** `pushLine` now accepts an `isAssistantMessage` flag. When set, `classifyLine` never produces `"prompt"` — assistant messages are conversational content, not interactive stdin prompts. The flag is passed as `true` only when parsing structured `stream-json` assistant-role messages.
